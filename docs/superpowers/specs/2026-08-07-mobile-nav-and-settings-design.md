# تصميم: واجهة تنقل مخصصة للجوال والتابلت + قسم "الإعدادات"

**التاريخ:** 2026-08-07
**الحالة:** معتمد للتخطيط (بانتظار writing-plans)
**النطاق:** إعادة تنظيم التنقل بالتطبيق بحيث يكون الشريط السفلي (البار السفلي) هو التنقل الأساسي على الجوال **والتابلت** معاً، وتجميع "المبيعات" و"الأرشيف" و"الموظفون" داخل صفحة "إعدادات" جديدة يوصلها المستخدم من تبويب بالبار السفلي، مع إضافة **أول زر تسجيل خروج** بالتطبيق. **لا يشمل** أي إعادة تصميم بصري لشاشات الكاشير أو المخزون نفسها (يبقى تصميمها كما هو، هذا التصميم يخص التنقل والتجميع فقط).

## المشكلة

1. البار السفلي (`BottomNav`) — المصمم أصلاً للجوال — يعرض 5 تبويبات (الكاشير، المخزون، المبيعات، الأرشيف، الموظفون)، وهذا كثير على شاشة صغيرة ويحتاج تبسيط.
2. نقطة التحول بين واجهة الجوال (BottomNav) وواجهة الديسكتوب (Navbar + Sidebar) حالياً عند عرض `768px` (Tailwind `md`) — يعني أي تابلت (حتى بالوضع العمودي) يشوف واجهة الديسكتوب المزدحمة بدل واجهة الجوال المبسطة، رغم إن التابلت يفترض يكون تجربة "جوال موسّع" مو "ديسكتوب مصغّر".
3. ما كو أي طريقة لتسجيل الخروج بالتطبيق إطلاقاً — لا زر ولا رابط بأي مكان.
4. قائمة الروابط مكررة بثلاث ملفات منفصلة (`Navbar.tsx`, `Sidebar.tsx`, `BottomNav.tsx`) بأسماء غير متطابقة أحياناً لنفس الرابط (مثال: "المخزون" مقابل "المنتجات"، "المبيعات" مقابل "تقارير المبيعات") — أي تعديل بالتنقل (متل هذا التصميم) لازم يتكرر 3 مرات ويصعب يضل متطابق.

## الهدف

1. البار السفلي يعرض **3 تبويبات بس** لكل المستخدمين: الكاشير، المخزون، الإعدادات.
2. صفحة جديدة `/settings` تجمع: المبيعات (أدمن بس)، الأرشيف (الكل)، الموظفون (أدمن بس)، وزر "تسجيل خروج" (الكل).
3. البار السفلي يظهر للجوال **والتابلت** معاً؛ Navbar+Sidebar (واجهة الديسكتوب) تظهر بس للشاشات الكبيرة جداً (لابتوب فأكبر).
4. تسجيل الخروج يشتغل فعلياً ويرجّع المستخدم لصفحة الدخول.
5. مصدر وحيد لقائمة الروابط، يستخدمه Navbar وSidebar وBottomNav الثلاثة بدون تكرار.

## القرارات المتفق عليها

- **نقطة التحول الجديدة:** نرفعها من `md` (768px) إلى `lg` (1024px) بكل مكان يفرّق بين واجهة الجوال/التابلت وواجهة الديسكتوب — `BottomNav` يصير `lg:hidden` بدل `md:hidden`، و`Navbar`/`Sidebar` يصيرون `lg:flex`/`lg:block` بدل `md:flex`/`md:block`. نفس التغيير لازم ينطبق على الحشوة (padding) بـ `app/(dashboard)/layout.tsx` (`pb-20`/`p-3` الحالية مبنية على `md:` وتحتاج تتحول لـ `lg:` بنفس الوقت، وإلا يصير فراغ أو تداخل غلط عند عرض التابلت بين اختفاء البار السفلي وظهور المحتوى).
- **`/settings` صفحة مخصصة (مو قائمة منبثقة/Bottom Sheet)** — نفس نمط باقي صفحات لوحة التحكم الموجودة (`/employees`, `/sales`, إلخ).
- **الديسكتوب (Navbar/Sidebar) يعكس نفس التجميع الجديد** — يعرضون بس (الكاشير، المخزون، الإعدادات)، وصفحة `/settings` نفسها هي اللي تظهر عليهم أيضاً لما يضغطون "الإعدادات" — تناسق كامل بين كل أحجام الشاشات، بدون منطق تنقّل منفصل للديسكتوب.
- **صلاحيات الأدمن ما تتغيّر** — "المبيعات" و"الموظفون" يبقون محصورين بالأدمن بس (نفس `ADMIN_ONLY_PATHS` الحالي)، فقط ينتقلون ليكونوا روابط داخل `/settings` بدل تبويبات منفصلة بالبار السفلي. تبويب "الإعدادات" نفسه يظهر لكل المستخدمين (كاشير يشوف بداخله الأرشيف + تسجيل الخروج بس).
- **تسجيل الخروج بدون منطق حماية إضافي** — `middleware.ts` الحالي أصلاً يرجّع أي مستخدم غير مسجّل دخول لـ `/login` تلقائياً بكل الصفحات المحمية، فبس نستدعي `supabase.auth.signOut()` من `lib/supabase/client.ts` ثم نروح لـ `/login` (نفس نمط `router.replace` + `router.refresh()` المستخدم أصلاً بصفحة تسجيل الدخول).
- **تفعيل التبويب النشط لـ "الإعدادات":** يعتبر نشط إذا المسار الحالي يبدأ بـ `/settings` أو `/sales` أو `/archive` أو `/employees` — مو بس `/settings` بالضبط — عشان المستخدم يعرف وين هو لما يكون بصفحة فرعية.

## الطريقة التقنية

### 1. مصدر وحيد لقائمة الروابط — `components/shared/navLinks.ts` (جديد)

```ts
export const PRIMARY_LINKS = [
  { href: "/pos", label: "الكاشير" },
  { href: "/inventory", label: "المخزون" },
  { href: "/settings", label: "الإعدادات" },
];

export const SETTINGS_LINKS = [
  { href: "/sales", label: "المبيعات", adminOnly: true },
  { href: "/archive", label: "الأرشيف", adminOnly: false },
  { href: "/employees", label: "الموظفون", adminOnly: true },
];

export function isSettingsPath(pathname: string) {
  return ["/settings", "/sales", "/archive", "/employees"].some(
    (path) => pathname === path || pathname.startsWith(`${path}/`),
  );
}
```

`Navbar.tsx` و `Sidebar.tsx` و `BottomNav.tsx` الثلاثة يستوردون `PRIMARY_LINKS` بدل قوائمهم المنفصلة الحالية (`NAV_LINKS` بـ Navbar، `LINKS` بـ Sidebar). لا حاجة لفلترة حسب الدور على `PRIMARY_LINKS` — الثلاثة روابط تظهر للجميع الآن (الفلترة الوحيدة صارت داخل `/settings`).

### 2. صفحة `/settings` — `app/(dashboard)/settings/page.tsx` (جديد)

- يقرأ `role` عبر `useAuth()`.
- يعرض `SETTINGS_LINKS` كقائمة بطاقات/روابط (نفس أسلوب البطاقات المستخدم بصفحات الإعدادات المشابهة بالمشروع)، مع فلترة `adminOnly` حسب `role === "admin"` (نفس منطق `ADMIN_ONLY_PATHS` الحالي بـ `Navbar.tsx`، منقول لهنا).
- تحت القائمة، زر "تسجيل خروج" بـ `variant="secondary"` (نفس أزرار الإجراءات الثانوية بالمشروع — تسجيل الخروج إجراء عادي وقابل للتراجع بإعادة تسجيل الدخول، مو إجراء إتلاف يحتاج تنبيه أحمر) يستدعي دالة `handleLogout`.

### 3. تسجيل الخروج

`handleLogout` بصفحة `/settings`:
```ts
async function handleLogout() {
  const supabase = createClient();
  await supabase.auth.signOut();
  router.replace("/login");
  router.refresh();
}
```
`AuthContext` أصلاً مشترك بـ `onAuthStateChange` فبيتحدّث تلقائياً (`user`/`role` يرجعون `null`) بمجرد `signOut()` — بدون حاجة لأي كود إضافي هناك.

### 4. تحديث نقطة التحول بالمكونات الثلاثة + الـ layout

- `BottomNav.tsx`: `md:hidden` → `lg:hidden`.
- `Navbar.tsx`: `hidden ... md:flex` → `hidden ... lg:flex` (الرابط الداخلي).
- `Sidebar.tsx`: `hidden ... md:block` → `hidden ... lg:block`.
- `app/(dashboard)/layout.tsx`: `main` className من `p-3 pb-20 md:p-6 md:pb-6` إلى `p-3 pb-20 lg:p-6 lg:pb-6`.

### 5. تنظيف

بعد نقل `/sales` و `/employees` لداخل `/settings`، `Sidebar.tsx` و`Navbar.tsx` ما يحتاجون فلترة `ADMIN_ONLY_PATHS` بعد الآن (تنتقل الفلترة بالكامل لصفحة `/settings`) — هذا يبسّط الملفين ويشيل `visibleNavLinks()` من `Navbar.tsx` (لأن `PRIMARY_LINKS` تظهر للجميع بدون استثناء).

## معالجة الأخطاء

- **مستخدم كاشير يفتح `/sales` أو `/employees` مباشرة برابط (مو من `/settings`):** الحماية الحالية داخل كل صفحة (`if (!isAdmin) return <...>`) تبقى كما هي بدون تغيير — تجميعها تحت "الإعدادات" تنظيم تنقّل بس، مو طبقة حماية جديدة.
- **`signOut()` يفشل (مشكلة شبكة):** نتحقق من الخطأ المرجّع ونمنع التوجيه لـ `/login` لو فشلت العملية فعلياً، مع رسالة خطأ قصيرة بالعربي (نفس نمط باقي رسائل الأخطاء بالمشروع).

## الاختبار

- ما كو اختبارات آلية لمكونات React بالمشروع حالياً (كل الاختبارات الموجودة تخص `services/`/`hooks/`/دوال منطقية بحتة) — نتبع نفس النمط ونتحقق يدوياً:
  - عرض الجوال (~375px): البار السفلي 3 تبويبات، `/settings` يفتح ويعرض الروابط الصح حسب الدور.
  - عرض التابلت (~820px، عمودي وأفقي): البار السفلي يظهر (مو Navbar/Sidebar).
  - عرض ديسكتوب كبير (≥1024px): Navbar+Sidebar يظهرون، البار السفلي يختفي.
  - تسجيل خروج من حساب أدمن وحساب كاشير: يرجع لصفحة الدخول، ومحاولة فتح `/pos` مباشرة بعدها ترجّع لـ `/login` (تأكيد إن `signOut()` فعلاً مسح الجلسة).
- `npm run typecheck && npm run lint && npm test && npm run build` لازم كلهم ناجحين قبل أي commit.

## خارج النطاق (مؤجَّل)

- أي إعادة تصميم بصري لمحتوى شاشات الكاشير/المخزون/المبيعات نفسها.
- أي إعدادات فعلية جديدة غير نقل الروابط الثلاثة + تسجيل الخروج (مثال: تخصيص اسم المحل، الشعار، إلخ) — لو المالك يحتاجها لاحقاً تكون تصميم منفصل.
- تعديل تخطيط `POSProvider`/`OfflineProvider` أو أي منطق غير متعلق بالتنقل.
