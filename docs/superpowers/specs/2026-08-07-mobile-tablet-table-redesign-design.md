# تصميم: إعادة تصميم الجداول للجوال والتابلت

## المشكلة
الموقع مبني أصلاً ليكون mobile-first، لكن مكونين ما زالا يستخدمان `<table>` HTML خام بدون أي نسخة بديلة للشاشات الصغيرة:

- `components/features/inventory/StockTable.tsx` — جدول المخزون (اسم، باركود، سعر، كمية، تعديل/حذف).
- `components/features/pos/CartGrid.tsx` — جدول سلة الكاشير (منتج، سعر، كمية، إجمالي، حذف). أزرار +/- فيه 32px فقط (أصغر من الحد الأدنى الموصى به 44px لأزرار اللمس).

على الجوال، الجداول تُقصّ أعمدتها أو يضطر المستخدم للتمرير الأفقي، وأزرار اللمس صغيرة. باقي الصفحات (الأرشيف، الموظفين، الفواتير) لا تستخدم `<table>` أصلاً وهي مبنية كقوائم بالفعل — لا حاجة لتعديلها.

## القرار
تحويل الجدولين إلى تخطيط **بطاقات/قائمة عمودية واحد يُستخدم على كل الأحجام** (بدون نسخة جدول منفصلة لسطح المكتب) — بما أن الأولوية المعلنة من العميل هي الجوال والتابلت وليس الحاسوب، ولتفادي صيانة تخطيطين لنفس البيانات.

### StockTable
كل منتج يصبح بطاقة (باستخدام مكوّن `Card` الموجود):
- سطر علوي: اسم المنتج (عريض) + الباركود (رمادي، خط mono).
- سطر ثانٍ: سعر البيع والكمية جنبًا إلى جنب (نفس منطق تحذير النقص الحالي بالأحمر).
- سطر سفلي: زرّا "تعديل" و"حذف" بعرض أكبر وارتفاع لمس لا يقل عن 44px، مع الحفاظ على `ConfirmInline` عند الحذف.

### CartGrid
كل عنصر في السلة يصبح بطاقة مدمجة:
- سطر علوي: اسم المنتج (+ الوحدة إن وجدت) وسعر الوحدة.
- سطر سفلي: عدّاد الكمية (أزرار −/+ بحجم 44×44px بدل 32×32px الحالية) على اليسار، والإجمالي وزر الحذف على اليمين.
- يبقى `overflow-y-auto` والـ sticky الحالي للسلة كما هو.

### خارج النطاق
- بقية الصفحات (POS الكاشير نفسه، الإعدادات، الأرشيف، الموظفين، المبيعات) تمت مراجعتها ولا تحتوي جداول HTML أو تخطيطات مبنية لسطح المكتب فقط — لا تغييرات مطلوبة فيها.
- لا تغيير في منطق العمل (الخدمات، حساب الأرباح، خصم المخزون) — تعديل بصري/تخطيطي فقط.

## الاختبار
- `npm run typecheck && npm run lint && npm run build` يجب أن تمر بدون أخطاء.
- مراجعة يدوية على عرض جوال (375px) وتابلت (768px) لعدم وجود تمرير أفقي وأن كل الأزرار قابلة للمس بسهولة.
